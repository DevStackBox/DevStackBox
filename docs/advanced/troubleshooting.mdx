# Troubleshooting

Record the exact action, error and time before changing configuration. The app's process status, website response, certificate trust and database authentication are separate results.

## Apache rejects a parent .htaccess

An error such as `project/.htaccess: <IfModule not allowed here` occurs before Laravel runs. The failing file may be above the selected public document root. v0.1.17 adds an explicit ancestor-directory baseline; restart Apache after upgrading and compare the path in a new log entry. Explicit custom directory policies can still affect that baseline. Do not add a broad rule for an entire drive or hardcode an XAMPP folder. See [Projects](../getting-started/projects).

## A service does not start

1. Open the service's Logs tab or the [Logs workspace](../user-guide/logs).
2. Check the configured port and identify any conflicting process using [Networking](environment). Stop only the service you intend to stop, or choose a different port and update its clients.
3. If the error names configuration, use the [editor and saved history](../user-guide/configuration-editor). Restart after a successful save.
4. For a missing executable or DLL, confirm the installed runtime files and the release's prerequisites. Preserve user data before repairing from an official installer.

Installed configurations and data normally live under `%LOCALAPPDATA%\devstackbox`; they are not necessarily in the install folder. Use the log path reported by the app and check custom destinations. A manually run Apache syntax check must use the same configuration file as the managed instance.

## MySQL stops or cannot read its data

Keep the error log and data directory. Check the actual configuration, port, permissions, disk space and any server-version change. Configuration backups are not database backups. Do not delete data or lock files merely because an old guide suggests it, and do not point MySQL 8.4 at another product's data directory.

For MySQL version migration, obtain a compatible SQL export from a working source/backup and test restoration separately. See [Upgrading](../getting-started/upgrading) and [SQL backups](../user-guide/database-backups).

## Configuration cannot be read, saved or restored

The editor offers Reload, Revert, Save and **Restore a saved backup**. There is no Restore Default button. A rejected validation leaves the original configuration in place; a successful parse still requires application testing. Inspect permissions and disk space if writes fail.

If a file is missing, retain any recovery copies and use the normal service preparation or a known-working backup. Do not copy another machine's absolute paths blindly. The [configuration guide](../user-guide/configuration-editor) explains drafts, history and restarts.

## PHP download, activation or extensions fail

PHP downloading is implemented. Open **Services → PHP → Versions** and inspect the installed/available patch and operation error. A network failure, failed verification, incomplete extraction and locked runtime require different remedies. Do not bypass integrity checks. Stop Apache and close PHP terminals before updating runtime files.

Confirm the branch is installed and supported before activation. For missing modules, check the runtime and ini actually used by the website, especially for pinned projects. Restart Apache after an extension change. See [PHP](../user-guide/php).

## phpMyAdmin says no data was received

A browser upload may exceed PHP upload/POST limits before MySQL receives SQL. Use **Databases → Backups → Restore from .sql** for native file streaming, or review the explicit recommended PHP import-limits action and restart Apache. A larger PHP upload limit does not fix incompatible SQL or database authentication. See [SQL restoration](../user-guide/database-backups).

The v0.1.17 bundle contains phpMyAdmin 5.2.2. Diagnose current warnings against the actual installed version and selected PHP; historical 5.2.1 mitigation notes are not proof of a current failure or resolution.

## A project returns 404 or 500

Confirm the hostname and document root, the folder's existence, framework dependencies, website PHP and database credentials. Laravel normally serves its public directory. Compare a new request with [project/server logs](../user-guide/logs). Trusted HTTPS can return an application error; see [Local HTTPS](../user-guide/local-https).

## Database lists or imports fail

Confirm MySQL is running, the port is correct and the app's stored local credentials still work. Creating a MySQL user does not grant database privileges automatically. Changes made in an external client can leave stored credentials out of sync.

SQL import errors can leave partial changes. Preserve the source and error before retrying; an initial database selection does not constrain later USE statements in the dump. See [Databases and users](../user-guide/databases) and [SQL restoration](../user-guide/database-backups).

## Backup or restoration failed

Check free space, file permissions and whether the archive included MySQL. Preserve the archive and the error. Full backups exclude logs, external project files and HTTPS private material. Restoration can be partial; repeatedly restoring is not a safe rollback strategy. Use [Full backup and restore](../user-guide/full-backup) for scope and recovery.

## Installer or updater fails

Current public Windows installers use NSIS `.exe` packages. Record the installer log/error, install location and any named locked file. Close the application/process holding that file before retrying. Do not disable antivirus broadly or uninstall first as a generic workaround; examine the actual security or file-access report and verify the official package.

Update signatures and Windows publisher trust are different checks. Do not bypass failed updater verification. Preserve projects and data, then follow [Installation](../getting-started/installation) and [Upgrading](../getting-started/upgrading). Historical MSI notes are for older builds, not the current install flow.

## Blank screen or unexpected UI text

Restart the app and record the installed version and reproduction steps. Use About/system information if available. Contributor builds can inspect frontend errors and run the documented [build checks](../development/building); end users should not need to install a development toolchain to report a broken screen.

A raw translation key is a UI defect. Report the screen and selected language. A stopped/empty backend preview in a browser is not a successful test of the native desktop application.

## Report a problem

Include app version, Windows version, steps, expected/actual result and relevant sanitized log lines. Do not publish passwords, full environment dumps or local CA private keys. Use the [issue tracker](https://github.com/DevStackBox/DevStackBox/issues) for ordinary defects and the [security policy](https://www.devstackbox.com/security) for vulnerabilities.

Legacy troubleshooting and technical-debt text is preserved as a [historical snapshot](https://github.com/DevStackBox/DevStackBox/blob/main/docs/archive/troubleshooting-before-user-guides-2026-10-23.md), not current operating instructions.
