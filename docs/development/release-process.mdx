# v0.1.17 release process

The source version is 0.1.17. Installer generation, installed qualification and publication are separate steps. [Release runbook](./release-runbook) contains the exact commands.

## 1. Review source and versions

- Review the app and website changes and the changelog.
- Match package.json, src-tauri/Cargo.toml and src-tauri/tauri.conf.json at 0.1.17; synchronize app entries in both lockfiles.
- Run npm run check, Rust unit tests and both Apache regression modes.
- Preserve historical release notes and hashes. Generated download manifests stay associated with their original assets until finalization.

## 2. Build the signed installer

Use npm run build:release with the private signing key configured as described in the runbook. NSIS is the only configured target. Updater signing does not imply Windows Authenticode signing. Never bypass a failed signature check.

## 3. Finalize from the exact artifact

Run npm run finalize-release and verify-updater-artifact.mjs. Confirm the new installer, signature, latest.json, release notes, changelog hash and packaging manifests all describe the same bytes. Do not use a previous build's checksum or invent a download URL for an unavailable release.

## 4. Qualify on Windows

- Test a fresh install and an upgrade from v0.1.16, with project/database backups.
- Verify custom ports, user PHP settings, site records and database contents survive.
- Verify the Apache migration creates its backup and does not duplicate the baseline after restart.
- Verify Laravel public-directory routes, static assets, HTTP and HTTPS, and a project with parent .htaccess. Check that private parent files remain inaccessible.
- Verify plain PHP and a root-level rewrite project; global and pinned PHP selections.
- Compare the displayed log path with the running server configuration and confirm a fresh request is observable.
- Check localhost, phpMyAdmin, large SQL restore failure reporting and updater progress.

Record actual results and remaining limitations in docs/RELEASE-VALIDATION.md. Do not label unperformed tests as passed. [Testing](./testing) and the repository checklist `docs/getting-started/local-install-test.md` provide details.

## 5. Publish and verify

Commit reviewed source and finalized release metadata, create the v0.1.17 tag, and upload the installer, its .sig and latest.json. Verify remote assets with finalize-release --verify-github v0.1.17 and test the in-app update from v0.1.16.

## 6. Website

Commit the source docs before hosted website builds. Pin DEVSTACKBOX_REF to v0.1.17 or the exact reviewed commit. Run content preparation, website tests, lint, build and HTTP smoke checks. Publish only after download assets are available; release availability is read from GitHub, not inferred from source version. Older screenshots must keep their provenance captions.
