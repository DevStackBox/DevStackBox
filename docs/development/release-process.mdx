# DevStackBox - Release Process

**The exact checklist for every release. Follow this every time without shortcuts.**

**Quick copy-paste runbook (PowerShell commands):** [Release runbook](./release-runbook)

**Current stable release:** v0.1.10

---

## Release Types

| Type  | When                                | Example           |
| ----- | ----------------------------------- | ----------------- |
| Patch | Bug fix only, no new features       | `0.1.8` → `0.1.9` |
| Minor | New working feature added           | `0.1.8` → `0.2.0` |
| Major | Breaking changes or large milestone | `0.x.x` → `1.0.0` |

Version format: `X.Y.Z` - always clean semver. No hyphens, no pre-release text.

---

## Step 1 - Pre-Release Checks

Before changing any version number, verify:

- [ ] All Phase 1 items in `roadmap` are complete for this milestone
- [ ] No CRITICAL issues in `advanced/troubleshooting` are newly introduced
- [ ] `cargo build` completes with zero errors
- [ ] `pnpm tauri build` completes with zero errors
- [ ] App starts and services can be started on a clean Windows test machine

---

## Step 2 - Version Bump

Change version in ALL THREE files at the same time:

### `package.json`

```json
{
  "version": "0.1.9"
}
```

### `src-tauri/Cargo.toml`

```toml
[package]
version = "0.1.9"
```

### `src-tauri/tauri.conf.json`

```json
{
  "version": "0.1.9"
}
```

Verify they match:

```bash
node -e "const p=require('./package.json'); console.log('package.json:', p.version)"
grep "^version" src-tauri/Cargo.toml
grep '"version"' src-tauri/tauri.conf.json
```

---

## Step 3 - Update CHANGELOG.md

Add an entry at the top:

```markdown
## [0.1.9] - 2026-MM-DD

### Fixed

- Description of bug fix

### Added

- Description of new feature

### Changed

- Description of change
```

Keep the format consistent. Do not delete old entries.

## Step 4 - Build Release (Windows signed NSIS)

**Canonical command** - use this every time (full runbook: [Release runbook](./release-runbook)):

```powershell
cd D:\Websites\DevStackBox   # or your clone path

Get-Process light -ErrorAction SilentlyContinue | Stop-Process -Force -ErrorAction SilentlyContinue
Remove-Item "src-tauri\target\release\wix" -Recurse -Force -EA SilentlyContinue
Remove-Item "src-tauri\target\release\bundle\msi" -Recurse -Force -EA SilentlyContinue

$env:TAURI_SIGNING_PRIVATE_KEY = (Get-Content "$env:USERPROFILE\.tauri\devstackbox.key" -Raw).Trim()
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = ""

pnpm tauri build 2>&1
```

**Why the cleanup lines matter**

- `light` (WiX) can stay running and lock files after a failed or partial build.
- DevStackBox ships **NSIS only**; removing stale `wix` / `bundle\msi` output avoids Tauri bundling the wrong target.

**Signing key**

- Private key file: `%USERPROFILE%\.tauri\devstackbox.key` (never commit this file).
- Tauri expects the **key contents** in `TAURI_SIGNING_PRIVATE_KEY`, not the path, during `pnpm tauri build`.
- Public key is already in `src-tauri/tauri.conf.json` under `plugins.updater.pubkey`.

**Alternative pipeline** (runs preflight checks first):

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY_PATH = "$env:USERPROFILE\.tauri\devstackbox.key"
npm run build:release
```

This calls [`scripts/build-release.mjs`](../../scripts/build-release.mjs) → `verify-release.mjs` → `tauri build --ci`.

**Expected output files** (replace `X.Y.Z` with your version):

- `src-tauri/target/release/bundle/nsis/DevStackBox_X.Y.Z_x64-setup.exe`
- `src-tauri/target/release/bundle/nsis/DevStackBox_X.Y.Z_x64-setup.exe.sig`

**Generate `latest.json` after a successful build:**

```powershell
.\scripts\make-latest-json.ps1 -Notes "DevStackBox vX.Y.Z - short summary"
Copy-Item release\latest.json latest.json
```

[`make-latest-json.ps1`](../../scripts/make-latest-json.ps1) reads the version from `tauri.conf.json`, copies the `.sig` into the manifest, and sets the GitHub download URL. Commit `latest.json` on `main` for repo history, but **installed apps download the manifest from the GitHub Release asset**, not from `main` alone.

If the build fails:

1. Check `src-tauri/target/release/build/` for Rust errors
2. Check that all three version numbers match exactly
3. Check that no new emoji were added to `.github/workflows/*.yml`

## Step 5 - Smoke Tests

Run this checklist on the **NSIS installer** (not dev mode) on a clean Windows 11 machine or VM:

**Installation:**

- [ ] NSIS installer installs without errors
- [ ] App opens from Start Menu
- [ ] App opens without antivirus immediately blocking it

**MySQL:**

- [ ] MySQL starts successfully
- [ ] phpMyAdmin opens in browser
- [ ] MySQL stops successfully

**Apache:**

- [ ] Apache starts successfully
- [ ] `http://localhost` shows the www directory
- [ ] Apache stops successfully

**Config:**

- [ ] Config editor opens `php.ini`
- [ ] Config change is saved
- [ ] Config backup is created

**General:**

- [ ] Dark mode and light mode both work
- [ ] Language switcher works (EN and HI)
- [ ] Sidebar navigation loads all pages without errors

## Step 6 - Generate SHA-256 Hash (optional)

```powershell
Get-FileHash "src-tauri\target\release\bundle\nsis\DevStackBox_0.1.9_x64-setup.exe" -Algorithm SHA256
```

Include the hash in the GitHub Release description if you want transparency for users.

---

## Step 7 - GitHub Release

1. Create a git tag:

   ```bash
   git tag v0.1.9
   git push origin v0.1.9
   ```

2. Go to [GitHub Releases](https://github.com/DevStackBox/DevStackBox/releases/new)

3. Fill in:
   - **Tag:** `v0.1.9`
   - **Title:** `v0.1.9`
   - **Description:** Copy from CHANGELOG.md
   - **Attach files:** `DevStackBox_0.1.9_x64-setup.exe`, `DevStackBox_0.1.9_x64-setup.exe.sig`, and **`latest.json`** (filename must be exactly `latest.json`)
   - Do **not** mark the release as a pre-release (otherwise GitHub `releases/latest` will not point here)

4. Click Publish Release.

Alternatively, from a signed build directory:

```powershell
gh release create v0.1.9 `
  "src-tauri\target\release\bundle\nsis\DevStackBox_0.1.9_x64-setup.exe" `
  "src-tauri\target\release\bundle\nsis\DevStackBox_0.1.9_x64-setup.exe.sig" `
  "latest.json" `
  --title "DevStackBox v0.1.9" `
  --notes "Copy from CHANGELOG.md"
```

## Step 8 - Post-Release

- [ ] Verify the download links in the GitHub Release page work
- [ ] Verify `https://github.com/DevStackBox/DevStackBox/releases/latest/download/latest.json` returns the new `version`, and that `signature` matches the uploaded `.sig` asset
- [ ] Verify **About → Check for updates** from an install on the previous version (or confirm “up to date” on the new version)
- [ ] Close GitHub Issues that were fixed in this release
- [ ] Update `feature-status` if feature status changed

## Auto-Updater

The in-app updater is **active** as of v0.1.8. Every release must include:

1. Signed NSIS build (`TAURI_SIGNING_PRIVATE_KEY` set during `pnpm tauri build`)
2. `latest.json` in the repo root with `signature` from the `.sig` file and a `platforms.windows-x86_64.url` that matches the uploaded `.exe` filename
3. Upload **`latest.json`** as a release asset named exactly `latest.json` - the updater fetches **`releases/latest/download/latest.json`**, not the copy on the default branch alone

Updater endpoint (configured in `tauri.conf.json`):

`https://github.com/DevStackBox/DevStackBox/releases/latest/download/latest.json`

After publishing, test **About → Check for updates** from an older install.

## What Can Go Wrong

| Problem                             | Fix                                                          |
| ----------------------------------- | ------------------------------------------------------------ |
| Build fails with "version mismatch" | One of the three version files is different                  |
| Antivirus blocks installer          | Publish SHA-256 hash - users can verify and allow            |
| GitHub Actions build fails          | Check for emoji in .yml files - see advanced/troubleshooting |
| Auto-update fails                   | Check `latest.json` signature matches `.sig`; URL matches `.exe` filename |
| `releases/latest` wrong version     | Ensure release is not marked pre-release; `latest.json` uploaded |
