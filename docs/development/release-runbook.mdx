# DevStackBox release runbook (Windows)

Single reference for **updater-signed NSIS builds** and **GitHub publish** so every release follows the same steps.

**Full checklist:** [Release process](./release-process)

**Private signing key:** `%USERPROFILE%\.tauri\devstackbox.key` - never commit.

---

The Tauri signature authenticates updates; it is not Windows Authenticode signing. Authenticode signing is pending for v0.1.14.

## 1. Preflight

From repo root:

```powershell
pnpm run check
# or: npm run check
```

Bump version in **all three** (must match):

- `package.json` → `"version"`
- `src-tauri/Cargo.toml` → `[package] version`
- `src-tauri/tauri.conf.json` → `"version"`

Update `CHANGELOG.md` before publishing (can draft after local build test).

---

## 2. Signed build (canonical)

```powershell
cd D:\Websites\DevStackBox   # your clone

Get-Process light -ErrorAction SilentlyContinue | Stop-Process -Force -ErrorAction SilentlyContinue
Remove-Item "src-tauri\target\release\wix" -Recurse -Force -EA SilentlyContinue
Remove-Item "src-tauri\target\release\bundle\msi" -Recurse -Force -EA SilentlyContinue

$env:TAURI_SIGNING_PRIVATE_KEY = (Get-Content "$env:USERPROFILE\.tauri\devstackbox.key" -Raw).Trim()
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = ""

pnpm tauri build 2>&1
```

Or: `.\scripts\release-build.ps1`

**Alternative with verify-release preflight:**

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY_PATH = "$env:USERPROFILE\.tauri\devstackbox.key"
npm run build:release
```

---

## 3. Finalize metadata (SHA + release notes)

After the NSIS build finishes, **do not type the SHA by hand**. Generate notes and update `CHANGELOG.md` from the **exact** installer file you will upload:

```powershell
npm run finalize-release
node scripts/verify-updater-artifact.mjs
# or after upload, sync SHA from GitHub:
node scripts/finalize-release.mjs --from-github vX.Y.Z --write-changelog
node scripts/finalize-release.mjs --verify-github vX.Y.Z
```

For v0.1.14, this verifies the exact installer signature, writes `release/notes-v0.1.14.md`, updates the changelog checksum, regenerates both `latest.json` files, and updates WinGet and Chocolatey version metadata. Before finalization, existing signed manifests remain associated with the previous release; do not manually relabel an old checksum or signature.

---

## 4. `latest.json` (required for auto-update)

```powershell
.\scripts\make-latest-json.ps1 -Notes "DevStackBox vX.Y.Z - summary for users"
Copy-Item release\latest.json latest.json
```

---

## 5. Publish GitHub Release

Upload: `.exe`, `.exe.sig`, and **`latest.json`** (exact name). Do not mark pre-release.

**Release notes:** use the generated file (never duplicate SHA in a separate doc):

```powershell
gh release create vX.Y.Z ... --notes-file release\notes-vX.Y.Z.md
# or:
gh release edit vX.Y.Z --notes-file release\notes-vX.Y.Z.md
```

Run `node scripts/finalize-release.mjs --verify-github vX.Y.Z` before marking the release done.

See [Release process](./release-process) Step 7–8.
