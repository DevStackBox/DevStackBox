# v0.1.17 documentation and cleanup audit

Audit date: 23 October 2026. Scope: first-party app Markdown/MDX, release guidance, website source and synced content. Vendor documentation, historical release evidence and generated build caches are not current product guidance.

## Readiness

Documentation targets v0.1.17. This is not a declaration that the installer or live website has been published. Build/sign/finalize the installer, qualify clean install and upgrade, test the actual Laravel HTTP/HTTPS site, verify updater delivery, and deploy the website against the same reviewed app revision. Record evidence in docs/RELEASE-VALIDATION.md.

## Corrections

- Feature status and roadmap now identify v0.1.17 source; historical versions remain historical.
- Configuration reference distinguishes persistent PHP settings from app-managed directives and explains the additive Apache migration.
- Troubleshooting and FAQ explain the exact parent .htaccess failure, public document root, and log-path limitations.
- Build guidance uses Node 24 and npm ci; bundled resources must be verified rather than replaced from XAMPP.
- Release runbooks use the verified build/finalize pipeline, concrete v0.1.17 artifacts and installed acceptance gates; obsolete MSI process-killing/cleanup instructions removed.
- Local install guidance no longer targets v0.1.11 or suggests deleting runtime resources for cleanup.
- Historical handoffs and planning documents remain available, with notices pointing to current guidance.

## Keep / do not sweep

- apache/, mysql/, php/, phpmyadmin/, tools/: bundled or installed runtimes and licenses; not disposable development clutter.
- www/, logs/, user data, config backups, databases and additional PHP branches: may contain active user work or recovery data.
- review-artifacts/* backup and runtime directories: include preinstall configuration, upgrade backups, private certificates and test profiles. Inspect individually; names alone do not establish disposability.
- release/, latest.json, packaging manifests and src-tauri/target/release/bundle/: preserve exact signed release evidence until archived and verified. Cargo target removal is rebuildable but would also remove these artifacts.
- docs/archive/, docs/RELEASE-VALIDATION.md, docs/LOCAL-HTTPS.md, ADRs, PROJECT-ROADMAP.md, website LAUNCH-MEDIA.md and IMPLEMENTATION-REPORT.md: retain design/validation/media provenance. Historical status is not a claim of current readiness.
- node_modules/: reinstallable, but deleting it is not necessary for repository cleanliness and interrupts local tools.
- Signing keys, certificates and .env files: never include in cleanup batches or publish as documentation.

## Release metadata boundary

Do not relabel previous installer hashes, latest.json signatures or WinGet URLs. npm run finalize-release updates them only after v0.1.17 installer bytes and signature exist. Website downloads continue to come from published GitHub assets. All deletion candidates above require a separate reviewed cleanup action.
