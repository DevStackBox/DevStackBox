# Upgrade DevStackBox

DevStackBox upgrades preserve user data in `%LOCALAPPDATA%\devstackbox\`. Your configs, logs, and MySQL data live there - not in the install directory. Web projects stay under `C:\devstackbox\www` by default.

From **v0.1.11**, the installer ships **MySQL 8.4 LTS**. There is no automatic MySQL 8.0→8.4 conversion tool. Back up databases before updating; if MySQL will not start after an update, export SQL from a backup or start with a fresh `mysql-data` folder (see [Troubleshooting](../advanced/troubleshooting)).

## Check for updates in the app

DevStackBox can check GitHub Releases for a newer version:

1. Open **Settings → Updates**.
2. Turn on **Auto-check updates** (stored in `localStorage` as `devstackbox.settings.autoCheckUpdates`).
3. When enabled, the app checks on launch (after a short delay) and every 6 hours.
4. Use **Check for updates** on the About page for a manual check.

When an update is available, the header shows an indicator. Use **Download and install** (or **Restart & update** after download completes) on the About page - the app downloads the signed NSIS installer, verifies it, runs it with UAC, and relaunches. When you are already on the latest release, a manual check shows an “up to date” message.

## In-app auto-update (recommended)

As of v0.1.8+, this is the normal upgrade path when **Auto-check updates** is enabled (default on):

1. Open DevStackBox - a check runs shortly after launch, then every 6 hours while the app is open.
2. When a newer version is available, confirm the update dialog and allow UAC when prompted.
3. After install, the app relaunches; your data under `%LOCALAPPDATA%\DevStackBox\` is preserved.

Back up projects and export databases before updating. The v0.1.12 installer stops processes owned by the selected installation and checks replaceable binaries for locks before copying. If a file stays locked, setup aborts; close the reported process and retry.

## Manual upgrade (fallback)

If auto-update fails or you prefer a browser download, install a newer release over the existing install:

1. **Stop services** - stop Apache and MySQL from the dashboard or tray menu.
2. **Back up first** - use **Settings → Backup & Restore** to create a full backup, or back up both your install folder’s `www` and `%LOCALAPPDATA%\DevStackBox\`. Connected projects outside `www` keep their files in their original folders; back up those folders separately because full backups do not include their contents.
3. **Download** the latest Windows installer from [devstackbox.com/download](https://www.devstackbox.com/download) or [GitHub Releases](https://github.com/DevStackBox/DevStackBox/releases/latest).
4. **Run the installer** - accept the UAC prompt. Choose the same install directory as before (default: `C:\devstackbox`).
5. **Launch DevStackBox** - start services and confirm your sites and databases are intact.

Your user data layout:

```
%LOCALAPPDATA%\DevStackBox\
  config\           Apache, MySQL, PHP configs
  config-backups\   timestamped backups
  logs\             service logs
  mysql-data\       MySQL database files
  backups\          app-created backups
```

Binaries under the install directory (Apache, PHP, MySQL, phpMyAdmin) are replaced by the installer; the user data folder is not.

## What is coming next

Signed download-and-install via the Tauri updater is **shipped** today. Version 0.1.12 adds automatic service shutdown and lock checks before manual upgrades. Final clean-machine and cross-account qualification remains part of release testing. See [Installer & updates](../reference/installer) and [Release process](../development/release-process).
