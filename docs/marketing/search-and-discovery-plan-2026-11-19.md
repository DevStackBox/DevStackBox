# DevStackBox search and adoption plan

Reviewed 19 November 2026. The first campaign should help Windows developers run two existing PHP projects on different branches. Show the two sites working, explain what the global CLI uses, then give readers a direct path to install and repeat the result.

## What the audit established

- Fetched all 53 URLs in the public sitemap with HTTP GET and inspected the initial HTML. All responded successfully at their listed address, with one H1, a description, a matching canonical (ignoring the root trailing slash), and no observed noindex directive. An invented URL returned 404. Actual indexing, impressions, Core Web Vitals and crawler-specific CDN access still need owner data. [Live sitemap](https://www.devstackbox.com/sitemap.xml)
- The homepage, XAMPP comparison, migration walkthrough, Laragon and Herd comparisons, PHP docs, HTTPS docs, and troubleshooting already exist. The migration guide already covers keeping the source, separating files from databases and rolling back. New pages should earn their own URL by solving a different task. [Homepage](https://www.devstackbox.com/) · [Migration](https://www.devstackbox.com/migrate-from-xampp)
- The download page linked to the exact Windows installer for v0.1.22 and GitHub reported the same latest stable tag. The homepage uses a v0.1.19 hero asset and the repository README leads with a v0.1.17 screenshot and includes a v0.1.17 release section. Older screenshots can still illustrate unchanged controls. Review their captions and the workflows they depict against the shipped build. [Download](https://www.devstackbox.com/download) · [GitHub releases](https://github.com/DevStackBox/DevStackBox/releases/latest)
- The website checkout is at `D:/Websites/devstackbox-website`. Its Next.js app already generates a sitemap, canonical links and structured data. Its smoke suite covers routes, anchors, assets, AI-guide aliases and missing pages. Its analytics component loads Plausible when configured. No private dashboard or keyword-volume export was used.

## Search and AI discovery

Put a short direct answer, supported Windows versions, prerequisites, steps and a verifiable result in visible HTML on each tutorial. Give headings stable anchors. Include the tested app version, review date and links to the relevant release and detailed reference. Keep important instructions available as selectable text alongside screenshots. This also gives someone citing an answer a durable source.

The live robots file allows all agents and points to the sitemap. The existing Markdown guide and llms.txt both returned 200. Keep the single source in DEVSTACKBOX.md and the existing alias check. Verify representative URLs in Search Console and Bing Webmaster Tools and inspect CDN logs for actual crawler responses. Give search access and training permissions separate consideration. Google requires ordinary indexing and snippet eligibility for AI search features. OpenAI identifies OAI-SearchBot as its search crawler. [Robots file](https://www.devstackbox.com/robots.txt) · [Google AI search guidance](https://developers.google.com/search/docs/appearance/ai-features) · [OpenAI crawlers](https://developers.openai.com/api/docs/bots)

## Delivery, distribution and release gates

| When | Owner and deliverable | Acceptance |
| --- | --- | --- |
| Week 1 | Maintainer records the search baseline, reviews README and feature-status freshness, inventories overlapping pages, and tests the two-site example on the published installer. | Evidence includes installed version, two browser results and terminal output. Check checksum and current release link. Resolve any discrepancies before writing promises. |
| Week 2 | Docs author adds the two-PHP tutorial in the app repo. Website maintainer uses the existing content-preparation pipeline, adds a homepage link and a relevant download CTA, and updates the existing migration page. | A reader can get from the homepage to the working example in one click. Verify published HTML, heading anchors and return links. Canonical docs edits survive a fresh website build. |
| Weeks 3–4 | Maintainer records one short captioned demo using the same example, with a transcript and links to the guide. Feature it in the GitHub README and on the existing Community page. Offer a practical walkthrough in relevant PHP communities that welcome project posts. | Demo and tutorial reproduce the same result. Use aggregate referral links per channel. Community questions feed the troubleshooting backlog. A Hinglish edition is a reasonable experiment if the audience data supports it. |
| Days 30–60 | Review landing pages, non-brand impressions, clicks, and visits that reach the download action. Choose the Laravel or WordPress guide using actual results. | Compare equivalent 28-day periods and annotate releases/campaigns. Measure installer-link clicks per guide landing session where privacy settings permit. Count GitHub asset downloads separately from installs. Track AI referrals when present and a small fixed list of citation queries monthly, with date and locale. |

**Before publishing each change**, run the website's existing tests, production build and smoke suite on a preview. Extend the smoke check to compare the canonical URL value with the expected route. Verify the exact guide is in the sitemap, screenshots are readable on mobile and at 200% zoom, keyboard navigation works, images have useful alt text and reserved dimensions, and no personal paths appear. Check homepage, guide and download templates for mobile loading and layout shifts. Check structured-data values against visible, release-backed facts. Repeat the URL, installer-link and checksum checks after deployment. Keep the previous deployment available for rollback.

**Product claims require their own evidence.** Use the public release as the reference for tutorials. Keep unreleased containment fixes and the remaining filesystem, recovery and installer qualification work clearly identified in release documentation. Broad claims of production hosting suitability, lossless migration or guaranteed recovery exceed the evidence. An accessible, well-tested marketing website can describe a local development tool accurately while those checks proceed.
