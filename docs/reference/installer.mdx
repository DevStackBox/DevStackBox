# Installer and updates

The primary DevStackBox download is the Windows NSIS installer. Use GitHub Releases to check which assets are available for a particular version. This page describes install paths, how user data is kept separate from app binaries, and how updates work today vs what Phase 4 adds.

## Installers

The download page displays the actual installer size from GitHub.

Installation requires **Windows 10/11 (64-bit)** and administrator rights for installation.

**Default install directory:** `C:\devstackbox` (you can choose another path during setup).

Download: [devstackbox.com/download](https://www.devstackbox.com/download)

## App vs data directory separation

DevStackBox separates **replaceable app files** from **user data** to keep runtime data separate from bundled binaries; always back up projects and databases before an update. See [ADR 006](../development/adr/006-app-data-separation) for the full decision record.

**Install directory** (contains binaries and the project folder; do not delete it wholesale):

```
C:\devstackbox\
  DevStackBox.exe
  apache/
  php/
  mysql/
  phpmyadmin/
  resources/
  www/              web projects (preserved by the installer)
```

**User data root** (never touched by the updater or installer uninstall options that preserve data):

```
%LOCALAPPDATA%\DevStackBox\
  mysql-data/       MySQL data directory
  config/           runtime Apache, MySQL, PHP configs
  config-backups/   automatic config backups
  logs/             service logs
  backups/          full backups created in-app
```

Override the user data path with `DEVSTACKBOX_DATA_DIR` if needed.

Runtime configs live under the user data root. Apache serves projects from the install folder’s `www`; MySQL data remains under the user data root. `DEVSTACKBOX_DATA_DIR` does not relocate `www`.

## Update check (shipped)

The app includes `tauri-plugin-updater` and an **Auto-check updates** preference (Settings → Updates). When enabled:

- Checks GitHub Releases on launch and every 6 hours
- Shows a header indicator when a newer version exists
- Manual **Check for updates** on the About page always available

When a newer semver is published, the About page and header guide the user through **download and install**: the signed NSIS package is fetched from the URL in `latest.json`, verified with the minisign public key in `tauri.conf.json`, executed, then the app relaunches. See [Upgrading](../getting-started/upgrading).

**Stable updater endpoint** (also used by `check_app_update` for the stable channel):

`https://github.com/DevStackBox/DevStackBox/releases/latest/download/latest.json`

## Auto-update hardening (Phase 4.3 - in progress)

Download, signature verification, and in-app install are **shipped** as of v0.1.8+. Remaining safety work:

- [x] Runtime configs, logs, and database data outside the install directory
- [x] Updater plugin wired in the app
- [x] Updater endpoint and signing public key in `tauri.conf.json`
- [ ] Pre-update service shutdown (Apache + MySQL) before the installer runs
- [x] Configuration backups and version migrations exist; v0.1.17 adds a separate syntax-checked Apache override migration. See the configuration reference for preservation limits.
- [ ] Documented end-to-end test: install v0.X.Y → update to v0.X.Y+1 with data intact

Target milestone for the remaining items: **v0.2.0** ([Roadmap](../roadmap)). Publishing steps are in [Release process](../development/release-process).

## Uninstall

Use **Settings → Apps → Installed apps** in Windows. Uninstall options can preserve `%LOCALAPPDATA%\DevStackBox\` for runtime data. Back up the install folder’s `www` separately and read the uninstaller options before proceeding.
